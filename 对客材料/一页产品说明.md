# 一页产品说明（给客户带走）

## 这是什么
一套**数据不出内网**的银行客服 AI 工作台：客户提交 → 内网脱敏 → 外网模型给建议 → 内网规则裁决 → 坐席人工确认 → 全链路审计。
适用于消费争议、交易查询、疑似未授权、待确认四类客服场景。

## 三段链路，各管一段
| 区域 | 有什么 | 没有什么 |
|---|---|---|
| 内网可信域 | 客户原始数据、规则知识库、复原服务、审计 | — |
| 安全交换区（DMZ） | 字段白名单、内容复检、签名换发、工具网关 | 原始客户数据 |
| 外网协同域 | 客户入口、模型调用出口 | 原始客户数据、复原能力 |

## 四个可现场验证的点
1. **数据不出域**：出域报文里姓名/卡号/手机号原值命中 0，只有 `NAME_001` 这类令牌。
2. **AI 只建议不裁决**：疑似未授权、规则冲突、意图不明一律转人工（实测 4/4）。
3. **工具受控**：11 个白名单工具可用，6 个高危工具（任意 SQL、原始数据查询、生产规则直写）直接不存在，越权返回 403 并留审计。
4. **变更可管**：规则改动走"草稿 → 沙箱门禁 5 项 → 业务审批 → 安全审批 → 发布 → 回滚"，版本与审批链可查。

## 边界（请如实转达）
- 当前是**可运行原型**，不是生产系统；全部数据为合成数据。
- 客服响应目前以"给建议 + 转人工"为主，**不代替人工做业务决定**。
- 接入真实环境前，需要与贵行共同确认：数据分级与出域审批、可用模型端点、账号与审计留存要求、容量目标。

## 建议的下一步
1. 选一个场景（建议：消费争议受理）做 2 周小范围验证
2. 业务侧定 20–50 条规则 + 30 条以上真实案例（脱敏后）
3. 完成一次安全评审（出域、权限、审计三项）
4. 按评审结论决定是否扩到其他意图
