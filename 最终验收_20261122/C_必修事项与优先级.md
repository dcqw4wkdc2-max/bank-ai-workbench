# C. 必须修复事项及优先级

只列**必须做**的；可选优化单独标。每条写了谁做、怎么做、做完怎么验。

---

## P0-1　吊销并更换已暴露的 DeepSeek API Key

**为什么**：Key 在聊天记录里明文出现过，任何看到记录的人都能用你的额度。

**谁做**：你（DeepSeek 控制台操作）+ 我（更新服务器）。

步骤：
1. 登录 platform.deepseek.com → API Keys → 删除 `sk-1b42…` 这把；
2. 新建一把，**不要再贴到聊天里**，用微信/文件单独发我；
3. 我把它写进服务器 `/opt/banksrc/model.env`（600 root），重启 inner，实测一句客户提问；
4. 旧 Key 删除后，即使有人拿到也失效。

**验**：客户页问一句，3–5 秒有回答且带【条款号】；日志无 401/403。

---

## P0-2　关停或限制旧版入口 19092 / 19093

**为什么**：19092 是原作者那版（12 例只过 8 条），客户贴身份证照常回答；公网可直接打开，演示时误点就自曝缺陷。

**谁做**：我（一条命令）。

做法（二选一）：
- **A（推荐）** 关掉 19092/19093 的 nginx 监听，只保留 19094/19096；
- **B** 保留但加 IP 白名单（只允许你的出口 IP）。

**验**：外部 `curl 19092` 应连接被拒；19094/19096 正常。

## P1-1　演示后轮换演示口令（b001–b004 / a001）

**为什么**：仓库已公开，口令在 19 份文档与源码里；19096 也对外开放。

**谁做**：我（改库 + 更新访问说明 + 重打包）。

做法：演示结束当天把 4 个坐席号与管理员口令全部换新，更新 `验收环境访问说明.md` 后重打 ZIP；旧说明标注作废。

**验**：旧口令登录 401，新口令 200。

## P1-2　补第三方盲测与换人接手签字（流程，缺证据）

**为什么**：任务书 11.3 要求"最终盲测由其他组或独立验收人员执行"，D4 要求"其他组成员按文档独立启动"。

**谁做**：你 + 另一位同学 / 隔壁组。

做法：
1. 把 `03_测试报告与测试证据/盲测记录_4张_AI代理执行_20261120.md` 第六节的命令交给隔壁组跑 2 分钟；
2. 让对方在文末签字栏签名并写日期；
3. 换人接手：让对方按 `README_从零启动指南.md` 启动一次，正常/异常各跑一条，在签收单签字。

**验**：签字页拍照入包；盲测记录判定从"部分"改为"第三方复核通过"。

## P2-1　MCP 首次调用 503（冷启动）

**为什么**：越权测试首次 503，随后 5 次均 403。演示时若第一次点就 503，观感差。

**谁做**：我。

做法：把 `mcp/proxy` 的首次调用加重试（1 次）+ 启动时预热一次 DMZ 通道。

**验**：连续 10 次调用，全部 403，无 503。

---

## P2-2　高风险话术补一句依据（可选）

**为什么**：挂失/冻结走确定性模板，客户看到的是同一段安抚话，缺少"为什么转人工"。

**谁做**：我（1 小时）。

做法：模板里按触发原因插入一句（如"因涉及卡片冻结与身份核验，需人工处理"），仍不承诺任何结果。
