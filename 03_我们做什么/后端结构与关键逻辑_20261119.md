## 三、三条有价值的发现（不是猜的）

1. **Agent 层确实有降级**。`inner/agent.pyc` 里有 `_mock_completion`，Docstring 写「MODEL_IMPL=real 走牛马仕算力，失败降级 Mock（fail-closed）」「输出过不了 schema 校验就抛错降级」。
   但实测 `fault=timeout` 后工单停在 `AI_ANSWERING`、客户拿不到任何反馈——**降级没有落到「工单状态 + 客户可见提示」这一层**。所以这一条要改的是回写，不是从零写降级。

2. **没有隐私判据**。`inner/privacy.pyc` 只有令牌化/解映射（正则 `\b(?:NAME|CARD|PHONE|ID|AMT|DATE|MERCHANT|ACCT|TXN)_\d{3,}\b`），
   `inner/rules.pyc` 只有 8 条业务规则与话术模板，找不到「检测到证件号/卡号原值即阻断」的分支——这是 C01 照常 RESTORED 的直接原因。

3. **状态码是局部拼装，不是统一枚举**。全项目常量里能搜到 `HUMAN_HANDOFF / CONFIRMED / EGRESS_BLOCKED / FB_INNER_REJECTED`，
   但搜不到 `TIMEOUT`、`SCANNING`、`RESTORED` 这类（可能由 db 层动态拼出）。这解释了客户侧与坐席侧状态为什么对不上。

> 以上是从字节码常量与函数签名得出的结论，不是逐行拆解；要动手改代码仍然需要 `.py`。

## 四、现在能把后端改到什么程度

| 做法 | 可行性 | 说明 |
|---|---|---|
| 读懂逻辑、精确点位 | 已做到 | 本文档 + 21 个 `.pyc` 原件（319KB） |
| 还原成可编译 .py | 不可靠 | Python 3.13；uncompyle6 / decompyle3 不支持，pycdc 对 3.13 也不完整 |
| 替换 exe 内 .pyc 打补丁 | 技术可行、风险高 | 需重打包 PyInstaller 归档，依赖与签名校验容易崩，不建议现场动 |
| 重写等价后端 | 可行但重 | 78 条接口 + 29 个 schema 齐全，约 3–5 天，还要重新对齐规则与审计 |

**结论：源码确实没有给我们；但源码结构已经找回来。** 现在去要 `.py` 可以点名到函数，对方没法再用「给不了」推。
