# 演示脚本 · 四条线（周四现场用，也用于周三交苏鸿的自测）

定位（苏鸿 11/17 11:06，三代管理核心群原话）：「我会在这里，引出我们的**w一体机**和**几个项目组做的案例演示**」「放在**安全**板块来介绍」。
所以这套东西不是"我们做了个系统"，是**给"AI 安全"这一段当证据**：客户数据不出域、AI 只建议不裁决、全链路可审计。
总时长 2 分 40 秒，讲的人一句话交代背景，剩下全是操作。

## 线一 · 客户提交（30 秒）

动作：客户入口 → 选"信用卡" → 输入"账单里有一笔不是我消费的 188 元，想申请核查" → 提交。
口播：「客户这边只做一件事：说清楚发生了什么。系统给他一个工单号，剩下的都不让客户做。」
看点：出工单号 FB…、状态"待人工接管"。

## 线二 · 低风险给出建议（60 秒，全场核心）

动作：坐席端 → 选 A01 → 提交并处理。
口播：「这条是低风险的争议咨询。注意看中间这一段——发给模型的东西里，客户姓名变成 NAME_001，卡号变成 CARD_001，电话变成 PHONE_001。原始信息一步都没出内网。模型回来的是建议，不是决定：它引用了 R-DISPUTE-01 和 R-DISPUTE-02 两条规则，有效期 5 分钟，带签名。」
看点：草稿包 JSON、令牌化上下文、规则引用、建议摘要＋动作 REQUEST_DISPUTE_FORM、人工四选（采纳/修改后采纳/转人工/驳回）。

## 线三 · 高风险强制人工（40 秒）

动作：客户入口提一条"卡一直在身边，出现 3280 元陌生消费" → 坐席端看这张工单。
口播：「同样一套系统，遇到疑似未授权，AI 一个字都不给客户，直接转人工。这不是它不会答，是规则不允许它答——R-UNAUTH-01 是强制人工。」
看点：HUMAN_HANDOFF、客户侧零答复、原因码。
补一句（有人问就答）：「有一次它引用了规则库里不存在的规则号，被裁决层挡下来直接转人工了。我们希望它这样：宁可转人工，不许编。」

## 线四 · 故障回退（30 秒）

动作：注入模型超时 / 返回非法 JSON（用唐丽雯的故障注入开关）。
口播：「模型挂了会怎样？任务安全失败，工单留着，坐席看到明确提示，不会拿到半截建议。所有失败都进审计。」
看点：状态可查、错误卡、审计里有这条。

## 收口（20 秒，只讲一句）

「所以银行要的不是更聪明的模型，是**敢让它上生产的那套边界**：数据不出域、AI 不裁决、每一步都能追。这套东西我们五天做出来，现在能跑，也能被另一个人接手跑。」

## 兜底（必背）

- 网断了：先放本地录屏，讲"这是我们昨天跑的同一套流程"，不再现场点。
- 被问"这是牛马仕跑的吗"：老实答——「当前这版 Agent 编排走的是 WorkBuddy 托管 Agent，模型走 partner-cloud 端点；牛马仕的接入是这条路线的下一层，任务书里也是按 Mock 先行设计的。」不装。
- 被问"代码谁写的"：「技术核心梁晓志，我负责分工和验收，测试是唐丽雯做的。」
- 被问"能不能上真实客户数据"：「不能，PoC 阶段全部合成数据，这也是我们敢公开演示的原因。」

## 演示前 30 分钟检查

1. 两个链接都能打开（客户/员工），sharecode 没过期
2. 12 例案例在，规则库 8 条 active
3. 至少一条已存在的 A01 成功记录、一条 B01 转人工记录（避免现场跑失败）
4. 本地录屏一份（四条线全录），存 U 盘＋手机各一份
5. 打印：本脚本一页、盲测记录表一页
