执行摘要
本方案围绕银行客服AI 工作台，采用“内网可信域+ 安全交换区/DMZ + 外网AI 协同域”的分区架构。微光「牛马仕」是
自研智能体（Agent），不是大语言模型；它可接入多种模型，承担经验证可用的任务理解、规划、模型调用和工具编排。模
型服务与智能体分层设计：具体模型端点、部署位置和可发送数据范围，必须按银行网络边界及审批结果确定。原始客户身
份信息、账户信息、隐私映射和最终业务规则留在内网；外网WorkBuddy 仅在获批范围内承担办公Agent 及辅助任务。五个
项目组使用相同项目目标和验收标准，在五天内分别完成端到端原型，并通过岗位任务卡、案例盲测卡和换人接手检验实际
交付能力。
总体推荐：采用“内网可信域+ 安全交换区/DMZ + 外网AI 协同域”的分区架构。内网保存员工入口、客户数据、规则知识
库、隐私映射和审计；在产品部署与安全评审通过后，可在内网接入微光「牛马仕」智能体，承担任务理解、规划、多模型
接入/调用和受控工具编排。牛马仕是Agent，不是模型；具体模型端点独立配置，按数据等级决定使用内网模型或经批准的
外部模型。隐私识别、脱敏、映射和恢复由独立内网服务执行；WorkBuddy Enterprise 作为外网办公Agent，不能直接访问内
网数据库。
必须先澄清：“严格物理隔离”与“实时调用外网API/MCP”不能同时无条件成立。若两张网络完全没有任何跨域通道，实时API
调用不可能发生。若要使用外网大模型，必须由银行批准专用跨域交换设施或受控网络通道；否则只能采用内网模型或人工
审批的离线文件交换。
核心要求
本方案的落地方式
客户隐私数据不出域
原始姓名、证件号、卡号、手机号、交易映射表和可直接识别身份的字段只保存在内网；外网
不存客户主数据。
Agent 与模型分层
微光「牛马仕」是自研智能体，可接入多种模型；模型端点、模型供应商和部署位置独立于
Agent，按银行审批配置。
模型调用受控
牛马仕只能调用已登记、已授权的模型端点；外部模型仅能接收获批的脱敏最小上下文。严格
气隙下只能使用内网可达的模型端点。
外网Agent 辅助
WorkBuddy 用于获批的办公材料、Skill/Workflow 和外网Agent 任务；不得直接执行银行业务动
作或访问原始客户数据。
内网和外网各自部署服务
内网Agent 运行节点的CPU/内存按牛马仕运行要求和并发确定；只有另行部署本地模型时才单
独规划GPU。外网CPU 节点承担WorkBuddy API 调用和任务编排。
银行员工处理客服问题
员工使用内网AI 工作台；牛马仕是否承担客服业务Agent 角色须通过业务、工具权限、会话隔
离和稳定性PoC 验证。
科技人员扩展应用
WorkBuddy 与牛马仕均不得绕过MCP 网关和后端授权；工具仅开放规则元数据、合成/脱敏样
例和聚合指标，生产写操作必须审批。
本方案的设计重点

采用内网可信域、受控交换区/DMZ、外网AI 协同域的分区架构，明确每个区域的数据与服务边界。

微光「牛马仕」定位为自研智能体，可接入多种模型；不得将其描述为模型或本地模型推理服务。

模型端点与Agent 运行环境分离；模型部署位置、供应商、协议及数据处理边界以实际接入清单和银行审批为准。

原始客户身份信息、账户信息和映射关系留在内网；任何模型或Agent 出域调用均须执行字段白名单、脱敏和审批。

五个项目组采用相同的端到端项目任务，采用组长、核心成员、助理成员分工，并通过岗位卡和案例盲测卡组织实战。

五天实施计划细化到每日任务、人员职责、交付物、检查点和放行条件。

1. 项目目标、约束与设计假设
1.1 业务目标

面向银行客服人员提供统一AI 工作台，辅助处理消费争议咨询、交易信息查询、疑似未授权和待确认等场景。

调用内网规则知识库、内部业务数据服务和本地隐私处理能力，形成可追溯的客服辅助结果。

在合规允许的范围内，将脱敏后的任务意图和上下文交给外网大模型进行复杂语义理解、信息归纳和解决方案建议。

为银行科技人员提供受控的扩展入口，利用WorkBuddy Enterprise、Skill、Workflow 和MCP 开发新的内部应用。

形成规则可维护、模型可替换、工具可审计、异常可回退、版本可追踪的持续运营机制。

智能体（Agent）
能够理解任务、规划步骤、调用模型和工具并组织执行过程的软件系统。微光「牛马仕」属于此类，
产品形态可类比Codex 一类任务执行型智能体；它可接入多种模型，但不等同于底层大语言模型。
模型端点/模型服务
由模型供应商或内部平台提供的推理接口/运行服务；可由Agent 通过适配器接入。模型端点的部署
位置、数据处理方式和授权范围须单独确认。
脱敏/假名化
用令牌或占位符替换身份字段。只要内网仍保留映射关系，外部数据仍可能被重新识别，必须按敏感
信息审慎管理。
MCP
Model Context Protocol，用于Agent 与外部工具/服务之间的标准化调用协议；MCP 本身不提供网络
隔离、身份认证或数据授权。
WorkBuddy
Managed Agents API
用于创建/管理WorkBuddy 托管Agent、版本、会话及查询运行事件的企业级接口，不应简单等同于
通用模型推理API。

2.2 安全交换区/ DMZ

承载跨域数据交换网关、API 代理、文件交换代理或MCP 受控网关。

只允许固定方向、固定协议、固定目标和固定字段的数据交换；默认拒绝所有未声明流量。

对外发内容执行字段白名单、DLP/敏感信息扫描、内容长度限制、签名、请求编号和有效期检查。

对返回内容执行来源校验、签名校验、结构化解析、恶意内容检查和重放检测。

不在DMZ 长期保存客户原始数据、映射表或完整业务数据库；必要的临时数据设置TTL 和自动清理。

禁止在一台普通双网卡服务器上自行做内外网转发。跨域设施必须采用银行批准的安全交换产品和网络方案。

3. 两条核心业务流程
3.1 银行员工处理客服问题
(1)
员工在内网AI 工作台登录，系统通过银行SSO/MFA 识别身份，并按岗位授予客服、主管或审核员权限。
(2)
员工输入客户咨询，或从内网业务系统选择已授权的客户/交易信息。系统生成全局唯一request_id 和session_id。
(3)
内网业务服务从客户数据服务按最小权限读取必要字段；原始字段不直接拼接到任何外部模型请求，也不直接交给未授
权Agent。
(4)
内网独立部署隐私识别与脱敏服务；结构化字段优先采用规则/正则确定性替换，非结构化文本可使用经验证的NER 能力
辅助识别。该服务与牛马仕Agent 解耦，不假设Agent 本身承担脱敏。
(5)
脱敏服务生成token 映射，映射表写入内网受控存储；出域前再次扫描原始姓名、证件号、卡号、手机号、金额/交易细
节等敏感字段。
(6)
内网规则服务提取允许外发的意图类别、规则摘要和最小必要上下文；禁止把整库知识、完整交易流水或内部敏感策略
直接发送外网。
(7)
经内网权限校验后，将最小化上下文交给牛马仕Agent 运行环境；牛马仕根据任务配置选择已接入的模型，并通过白名
单MCP 工具调用必要服务。若需要调用外部模型，必须经银行批准的安全交换路径，且仅发送获批的脱敏内容；若不允
许出域，只能调用内网模型端点。
(8)
牛马仕Agent 调用已配置且获批的模型端点，并可通过受控MCP 工具读取规则元数据、合成案例或执行允许的辅助操作；
返回结构化建议、依据摘要、待确认事项及风险标记。
(9)
Agent 及模型调用结果须经过Schema、长度、字段白名单、敏感内容、request_id 和版本校验；未经校验的内容不得进
入客服工作台。
(10) 内网校验request_id、session_id、牛马仕Agent 版本、实际模型供应商/模型版本、工具调用记录、输出字段和规则
引用；本地规则引擎再次决定是否可展示建议或必须转人工。
(11) 只有在当前会话、请求编号和员工权限均匹配时，内网恢复服务才可将必要token 映射为本地展示字段；恢复后的数据
不再外发。
(12) 员工核对结果后，选择采纳、修改、转人工或驳回；系统记录人工确认结果，形成可追溯审计记录。

6.1 为什么评估微光「牛马仕」作为内网Agent 平台

微光「牛马仕」是自研智能体（Agent），产品形态可类比Codex 一类任务执行型智能体；它能够接入多种模型，负责
任务理解、步骤规划、模型调用和工具编排，但它本身不是大语言模型。

将牛马仕作为内网Agent 候选，可复用项目方自研的智能体能力；但不能据此推断其必然支持银行内网部署、特定模型
协议或客服业务工具。需先核验产品部署方式、API/SDK、模型适配清单、MCP/工具机制、权限隔离和审计能力。

牛马仕可负责任务编排和模型/工具调用，但不能替代独立的数据安全控制。姓名、卡号、手机号、证件号等结构化字段
仍优先采用规则/正则和确定性映射；脱敏、出域扫描、映射恢复必须由独立内网服务执行。

不得把脱敏完全交给生成式模型：模型可能漏识别、误改写或受提示注入影响。出域前必须执行确定性扫描、字段白名
单和阻断。

正式接入前须取得牛马仕的产品版本、部署方式、Agent API/SDK、支持模型类型及接入协议、模型路由/切换机制、MCP
与工具权限、并发限制、日志策略、沙箱能力和回滚方式，并用同一批任务进行PoC。
6.2 为什么外网服务器不需要GPU
外网服务器的主要职责是接收经批准的脱敏任务、管理会话和队列、组装提示词、调用WorkBuddy Enterprise API、校验响
应并记录必要的审计元数据。大模型推理由WorkBuddy 托管服务或银行批准的外部模型平台承担，因此外网业务服务器通常
以CPU、内存、网络和高可用为主要配置指标，不需要本地GPU。

11.3 日常管理与组间评价

每组由对应学长学姐担任组长，负责每日站会、任务拆分、风险升级和最终交付；组长不包办开发。

五组使用同一项目模板、同一接口契约和同一测试数据格式；各组在独立分支或独立目录开发。

每天至少进行一次组内代码走查和一次组间交叉评审；接口或字段变更必须先更新契约。

每项任务必须登记负责人、协作人、截止时间、验收标准和证据位置，避免出现“大家都负责”等于无人负责。

五组均须完成端到端流程；不得出现某组只做前端、某组只做模型、某组只做测试的模块化分工。

最终盲测由其他组或独立验收人员执行；开发者不得提前查看预留盲测标准答案。

评价同时看功能、业务正确性、安全、可维护性、换人接手和团队协作，不以代码量或演示效果单独排名。

14.1 错误反馈闭环
1. 发现错误后立即生成错误卡，记录request_id、模型/Agent 版本、规则版本和复现步骤。
2. 将错误归类为隐私漏检、意图误判、规则缺失、提示词歧义、工具权限、接口故障或知识过期。
3. 确定临时措施：关键安全错误立即关闭外部调用或相关工具；业务不确定项转人工。
4. 修复后由未参与修复的人员执行回归测试，并补充同类正反样例。
5. 通过后发布新版本；保留旧版本、测试证据和回滚路径。

最终结论：本架构的核心不是简单地把内网数据脱敏后发给外网模型，而是建立一套可控的数据跨域、Agent 调用、模型接入、MCP 工具授
权、规则审批和审计机制。内网掌握数据、身份、规则和最终业务决策；微光「牛马仕」作为可接入多种模型的智能体，负责经验证授权的
任务编排；WorkBuddy 作为另一套外网企业Agent，仅承担获批的办公协同任务。模型端点与Agent 分层，数据是否出域、模型部署位置和
工具权限必须逐项审批。若银行不允许客户衍生信息出域，则牛马仕只能调用内网可达且获批的模型端点，不能假设可实时调用外部模型，
也不以WorkBuddy 私有化部署作为默认替代方案。
