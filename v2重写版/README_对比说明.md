> 说明：v2 是按已摸清的接口契约重写的后端（Python + FastAPI + SQLite），**不依赖任何外部模型**，
> 回答来自规则模板。原客户端（v1.5.0，编译产物）保持不动，两套可并排跑、并排看。

## 二、v2 具体改了什么（每条都能指到代码）

| # | 改动 | 位置 | 效果 |
|---|---|---|---|
| 1 | 异常分支置状态 | `adjudicate()` 的 fault 分支 | TIMEOUT / REJECTED + 错误卡 + 转人工 |
| 2 | `case.fault` 生效 | `adjudicate(case, fault=...)` | C03/C04 真按声明注入 |
| 3 | 隐私三级判据 | `privacy_judge()` | 证件号→BLOCKED；备注粘卡号→BLOCKED；回拨回访→转人工 |
| 4 | 通道统一 | `fb_submit()` 复用 `adjudicate()` | 客户页与服务台结论一致 |
| 5 | 并发 | FastAPI 同步端点 + SQLite WAL + 写锁 | 10 并发 100%，不需外部网关 |
| 6 | 时区 | `now_iso()` 用本地时区 | 时间与工单号一致 |

## 三、v2 没有解决的

1. **T12 网络隔离**：v2 是三个独立进程（可分别容器化），但没做 docker 三网络，网络级验证仍缺。
2. **真实模型**：v2 用规则模板回答，接真实模型端点要另配（好处是离线可跑、零费用、零出域）。
3. **T03 外发目录**：v2 没有独立的"外发目录"概念，映射表只在内网库。

## 四、怎么跑

```bat
:: 三个窗口分别跑，或双击同名 bat
启动-v2-坐席.bat    → http://127.0.0.1:18201/login （b001 / abc122333）
启动-v2-交换区.bat  → http://127.0.0.1:18202/dmz/api/v1/health
启动-v2-客户.bat    → http://127.0.0.1:18203/
```

前端沿用原客户端的三套页面（只把 DMZ/OUTER 端口常量改成 18202/18203），所以界面和演示脚本不用重学。

## 五、结论

- 原客户端：**能演示，异常路径全断**，且没有源码改不了。
- v2：**异常路径接通**，13.1 两项原本卡住的门槛在 v2 上通过；代价是必须放弃编译产物、用自己的实现。
- 给客户/上级的口径：**"我们用 v2 证明这套架构能把两项门槛做通；工程化落地需要源码或按 v2 继续做。"**
