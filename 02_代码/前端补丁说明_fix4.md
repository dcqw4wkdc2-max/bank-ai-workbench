# 前端补丁说明（v1.5.0-fix4 · 2026-11-18）

## 一、改了哪个文件

`_internal/h5/index.html`（客户反馈页，8103 端口）
备份：同目录 `index.html.bak-20261118`（回滚用，覆盖回去即可）

## 二、改了什么

在后端返回的答复文本渲染前增加一层**令牌兜底**函数 `desensitize()`：

| 内部令牌 | 客户看到的 |
|---|---|
| `NAME_001` | 客户 |
| `39.AMOUNT_001` / `15600.00 AMOUNT_002` | 该笔金额（含数字前缀一起替换） |
| `CARD_001` | 卡号尾号**** |
| `PHONE_001` | 预留手机号 |
| `ID_001` | 证件信息 |
| `MERCHANT_001` | 该商户 |
| 其它 `XXX_001` 形态 | 相关信息 |

同时处理了两处观感：`尊敬的 客户，您好！` → `您好。`；重复标点与多余空格合并。
应用位置三处：会话气泡、系统消息、列表摘要。

## 三、为什么这样修是合规的

任务书 7.4「复原前置条件」与 1.2「数据不出域」要求：复原失败时不得把内部令牌暴露给使用者。
本次后端复原未执行，前端按「复原不可用 → 不给原文、给中性描述」的口径兜底，属于降级展示，不是伪造数据：
客户看不到令牌，也拿不到被令牌化的原值（原值仍只在内网）。

## 五、局限（必须写明）

1. **只修了表现层**：后端复原仍未实现，原始值依旧没有被还原，客户拿不到具体金额/卡号——符合"不外泄"，但业务上仍属"信息不足"。
2. 令牌替换依赖固定前缀，若后端新增令牌类型（如 `ACCT_001`），会被兜底成「相关信息」，需要同步本表。
3. 打包程序是 PyInstaller 冻结包，本补丁改的是外部静态资源，**不会被 `.pyd` 覆盖**；但重新打包/换版本会丢失，需在新包上重打。
4. 管理端/坐席端页面未改（那边本来就是内网可见，露令牌不算外泄）。
