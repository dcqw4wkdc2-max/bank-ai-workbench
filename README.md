# 银行客服 AI 工作台（PoC）

面向银行客服人员的统一 AI 工作台原型，用于 **2026-11-19 浦发银行南宁分行内训**的现场演示。
第 4 组（组长 杨慧敏）负责本仓库。全部使用合成数据，**禁止提交任何真实客户信息**。

---

## 一、这是什么

一条端到端链路：客户提交诉求 → 内网取数 → 令牌化 → 出域报文 → 模型（内网/外网）→ 规则裁决 → 人工确认 → 复原 → 审计。

四类意图：消费争议咨询 / 交易信息查询 / 疑似未授权 / 待确认（意图不明）。
凡是疑似未授权、意图不明、规则冲突、超时或输出非法，**一律转人工**，不得由模型给出业务结论。

## 二、五条硬约束

1. 网络分区：内网可信域 / DMZ / 外网 AI 协同域，不默认互通。
2. 数据不出域：姓名、证件号、卡号、手机号、交易映射只留在内网。
3. Agent 与模型只给建议，不做最终裁决。
4. MCP 只开白名单工具，禁任意 SQL、禁直写生产规则。
5. 每次调用可追溯：request_id、会话、坐席、Agent 版本、模型端点、命中规则、结论、时间。

## 七、协作规矩

- `main` 只放可运行版本；每人一个 `feat/<名字>-<做什么>` 分支，改完提 PR。
- 提交信息写清改了哪条缺陷编号，例如 `fix: P0-01 客户通道令牌复原`。
- 接口字段、案例编号、规则编号不许各改各的，要改先提 PR 说明。
- **禁止提交**：账号密码表、`.env`、真实客户数据、运行日志、node_modules 等（见 .gitignore）。
