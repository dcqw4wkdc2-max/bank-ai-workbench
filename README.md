# 银行客服 AI 工作台（第4组）

浦发银行南宁分行内训演示用的原型仓库。**只放三类东西，别的不要往这加。**

## 从这里开始看

### 01_任务与通知 —— 要做什么
- `任务书.md`：苏鸿发的 30 页任务书（文本版，可搜索）
- `分组方案_组长核对稿.docx`：五组怎么分的
- `通知与派活.md`：上级原话摘录，一次看懂背景和交付要求

### 02_代码 —— 跑起来
- 源码快照解压到本目录（见 `放这里.txt`）
- 启动命令与依赖写进本页最下方

### 03_我们做什么 —— 谁做什么、做到哪
- `分工.md`：五个人各管一条线
- `每人交什么.md`：每个人的交付物、时间点、验收点
- `这周的待办.md`：计划看板上的待办清单
- `演示脚本_四条线.md`：周四现场 2 分 40 秒怎么演
- `测试报告.docx` / `缺陷台账.csv`：现在有什么问题、谁在改

## 三条规矩

1. `main` 只放能跑的版本；每人开 `feat/名字-做什么` 分支，改完提 PR。
2. 提交信息带编号，例如 `fix: P0-01 客户通道令牌复原`。
3. 不许提交：账号密码表、`.env`、真实客户数据、日志、node_modules。

## 项目硬约束（不要违反）

- 数据不出域：姓名、证件号、卡号、手机号、交易映射只留在内网。
- AI 只给建议，不做最终裁决；疑似未授权、意图不明、规则冲突、超时/非法输出一律转人工。
- MCP 只开白名单工具；每次调用可追到 request_id / 会话 / 规则 / 模型 / 结论。

## 怎么跑

> 源码并入后补：安装依赖 → 配置环境变量 → 启动命令。
> 这一节必须由**没参与开发的人**照着跑通一次，才算合格（任务书 D4 换人接手要求）。

## 材料放哪

- 仓库：任务书、通知、代码、分工、交付物、测试报告、台账、演示脚本
- WorkBuddy 项目「资产」：其余过程材料（测试清单 20 项、盲测卡 20 张、规则表骨架、交付说明）
